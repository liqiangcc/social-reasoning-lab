# 议题驱动工作流

## 1. 为什么使用议题

GitHub 议题是训练过程的控制面，用来承载：当前案例或书籍、当前训练目标、已揭示范围、会话摘要、关键发现、推理缺口和下一步行动。

议题不是第三方真实意图的事实数据库，也不是完整聊天记录备份，更不是模式最终真理来源。

## 2. 主案例议题

推荐关系：

```text
1 个案例 ↔ 1 个主案例议题
```

标题示例：

```text
[案例] 同事回复明显变短 — 判断是否需要主动确认
[案例] 模拟：领导说“这个方案再想想”
```

真实案例标题也必须去标识化。

主案例议题至少包含：案例编号、案例类型、训练目标、最小上下文、隐私检查、当前阶段、已揭示范围、最新会话摘要、未解决假设、下一步行动。

## 3. 案例生命周期

```text
捕获案例
↓
隐私与边界检查
↓
创建主案例议题
↓
揭示第一条输入
↓
分析会话
↓
回应 / 预测
↓
揭示新输入
↓
更新判断
↓
重复若干轮
↓
复盘
↓
候选模式 / 推理缺口
↓
暂停 / 归档 / 后续回放
```

## 4. 不提前看后文

对于真实历史复盘或书籍案例，即使最终结果已经知道，训练时仍应尽可能按时间切片。

不能先读取全部结果，再声称“当时应该这样判断”。

## 5. 会话不默认建独立议题

一个案例可以有多次会话，例如学习、预测、回应规划、回放、复盘、迁移。默认都挂在主案例议题下。

只有具有独立生命周期的工作才额外建议题，例如机制设计缺口、隐私规则缺口、模式分类设计、工具故障或长期书籍阅读项目。

## 6. 主书籍议题

候选书籍与正式阅读分开：

```text
阅读候选清单
→ 候选书籍
→ 选中一本书
→ 建立主书籍议题
```

推荐关系：

```text
1 本书 ↔ 1 个主书籍议题
1 本书 ↔ 多次阅读 / 案例训练会话
```

主书籍议题不只追踪“读到第几页”，还要追踪当前章节或案例、当前训练问题、已经建立的推理模式、仍未理解的概念、待验证的迁移能力和下一步行动。

## 7. 单个案例不能直接晋升正式模式

单个案例的总结只能产生候选模式。正式模式必须跨多个案例复核，并检查支持案例、反例、语境差异、误判风险和安全默认回应。

## 8. 议题状态不是事实状态

议题关闭只表示当前工作不再推进，不能解释为“已经确定对方真实意图”。

同样：会话完成 ≠ 真相解决；案例归档 ≠ 模式已证明。

## 9. 最小检查点

每次会话后，主议题只需要补充简洁检查点：已揭示到哪里、当前问题、主要假设、关键证据变化、推理缺口、下一步行动。

不要把完整人工智能聊天记录长期塞入议题。

## 10. 第一个试点的成功标准

只需证明：

1. 一个案例能按顺序揭示；
2. 事实与解释能够分离；
3. 至少能保留两个合理假设；
4. 新信息可以显式更新旧判断；
5. 原判断不会被事后覆盖；
6. 议题检查点足以换会话继续；
7. 最终只能产生候选模式，而不是草率的人性结论。
