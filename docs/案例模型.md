# 案例模型

## 1. 为什么需要案例模型

人际训练的对象不是“某个人”，而是一个在特定时间和上下文中逐步展开的互动场景。

因此本仓库以“案例”作为最小长期训练对象。

```text
案例
→ 输入 / 事件
→ 分析会话
→ 回应
→ 新输入 / 结果
→ 更新
→ 复盘
```

## 2. 案例

一个案例表示一个边界清晰的人际互动问题。

建议字段：

```text
案例编号
案例类型            # 真实 / 模拟 / 书籍来源
上下文摘要
训练目标
人物别名
隐私状态
当前阶段
主议题
```

案例不保存“某人的人格结论”。

## 3. 输入 / 事件

输入是当时真正出现的信息，可以是一句话、一段安全去标识化表达、一个行为、一个时间变化或一个明确外部事件。

核心要求：只记录可观察内容，不把推断写进观察字段。

## 4. 分析会话

一次会话是在某个信息截面上的分析。推荐模式：学习、预测、回应规划、回放、复盘、迁移。

## 5. 推理快照

每次会话保存的是可观察、可复盘的推理结构，不保存完整聊天记录，也不保存模型私有思维过程。

建议结构：

```text
已观察事实
即时解释
自身情绪反应（可选）
候选假设
支持证据
反对证据
缺失证据
当前问题
互动目标
回应候选
最终回应
选择理由
误判风险
下一步要观察的信息
```

置信度第一版只需要：低、中、高，不伪造精确概率。

## 6. 回应

回应是一个决策，不代表对对方真实意图的确认。

好的回应同时考虑：当前目标、误判成本、关系成本、边界、是否能继续获得信息、是否会无谓升级冲突。

## 7. 结果与更新

结果是随后真实发生的新信息。结果只能更新过去判断，不能重写过去判断。

更新必须显式描述：

```text
更新前判断
→ 新证据
→ 更新后判断
```

重点是保留变化，而不是只保存最后结论。

## 8. 推理缺口

每个案例允许记录：缺失上下文、漏掉信号、过度解读、过早确定、忽略替代解释、回应过强、回应过弱、边界未表达等问题。

这些缺口比“猜对了没有”更有训练价值。

## 9. 可复用模式

单个案例产生的经验默认只能是“候选模式”。

正式晋升前至少要求：

1. 在多个独立案例中重复出现；
2. 能说明适用条件；
3. 能说明反例或失效条件；
4. 不依赖某一个具体人的人格猜测；
5. 不把相关性写成因果；
6. 不抹平文化、组织、关系语境差异。

## 10. 核心关系

```text
1 个案例 ↔ 1 个主案例议题
1 个案例 ↔ 多条输入
1 个案例 ↔ 多次会话
多个案例 → 1 个候选模式 → 晋升检查 → 可复用模式
```

不设置“已经知道对方真实意图”这种永久完成状态。
