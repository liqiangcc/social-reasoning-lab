# Repository Boundaries

## 1. 本仓库负责什么

`social-reasoning-lab` 负责训练人际场景中的**显式输入处理、假设管理、回应选择、反馈更新和复盘迁移**。

核心问题是：

```text
在信息不完整、意图不可直接观察的人际互动中，
如何减少脑补和误判，并随着新信息持续修正自己的判断？
```

主要训练场景包括：

- 日常沟通
- 职场协作
- 冲突处理
- 困难对话
- 谈判与边界表达
- 言外之意 / conversational implicature 分析
- 对话复盘
- 书籍案例与模拟案例训练

## 2. 本仓库不负责什么

本仓库不是：

- 心理诊断系统
- 人格分类数据库
- “识人术”或“读心术”资料库
- 操控、欺骗、胁迫或利用他人弱点的方法库
- 私密聊天记录备份仓库
- 对第三方真实意图的权威判决系统
- 社会关系评分系统

任何关于“对方真实意图”的结论默认只能是**假设或后续得到证据支持的判断**，不能因为 AI 给出解释就升级为事实。

## 3. 三层必须分离

所有 Case 至少保持：

```text
Observed Fact
≠
Interpretation
≠
Inferred Intent
```

示例：

```text
Observed:
对方两天没有回复。

Interpretation:
我觉得这次互动变冷了。

Hypothesis:
对方可能不想继续沟通。
```

第三层不能反写成第一层。

## 4. 隐私边界

本仓库是公开 GitHub 仓库，因此真实案例默认执行去标识化。

禁止提交：

- 真实姓名
- 手机号、邮箱、住址
- 微信号、QQ、社交账号
- 身份证件或账户标识
- 公司内部敏感信息
- 未经同意的完整私密聊天记录
- 能通过组合信息轻易重新识别个人的细节

推荐使用：

```text
Person A
Person B
同事 A
朋友 B
时间窗口 / 相对日期
必要的最小上下文
```

如果一个案例无法在不暴露第三方隐私的情况下公开，就不应进入本仓库。

## 5. 顺序信息边界

训练模式优先采用 no-lookahead：

```text
当时已知信息
→ 当时判断
→ 当时回应
→ 新信息揭示
→ 更新
```

禁止：

```text
先知道最终结果
→ 再伪造“当时就应该看出来”
```

后见之明必须进入 Retrospective 层，而不能污染原始判断层。

## 6. AI 的角色边界

AI 可以：

- 帮助区分事实与解释
- 枚举合理候选假设
- 找支持证据和反证
- 分析不同回应的风险
- 根据新信息更新判断结构
- 帮助复盘 reasoning gap

AI 不应：

- 声称知道第三方未表达的真实思想
- 把概率性推断包装成确定事实
- 把刻板印象当证据
- 以操控他人为训练目标
- 鼓励隐蔽控制、欺骗或利用脆弱性

## 7. 与其他学习仓库的边界

本仓库关注：

```text
Human interaction reasoning process
```

书籍原文的稳定读取、章节结构、句子定位等 Source 能力应由专门的阅读基础设施承担；本仓库只保存训练控制、Case、Session 和经过验证的 Derived Pattern。

## 8. 当前不做的事情

机制 Pilot 完成前，不做：

- 大量迁移过去聊天记录
- 大规模 Pattern 分类
- 人格标签体系
- 自动关系评分
- 自动“意图识别”模型
- 复杂统计系统

先证明一个小 Case 能自然完成：

```text
Observe
→ Hypothesize
→ Respond
→ Reveal
→ Update
→ Review
```
